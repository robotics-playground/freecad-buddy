## Intent

**Problem:** `preview_dry_run` does not exist. `contracts/diff.py` declares `GeometryDiff` (`fcb.geometry-diff/1`) and nothing produces it; `deltas`/`counts`/`validity`/`tnp_precheck` are bare `dict` so the emitted schema constrains nothing (DW-12), and `ScalarDelta`/`CountDelta` are exported but unreferenced. Without a preview there is no evidence for a user to confirm from, so Story 3.7's confirm gate has no token to bind to and G2.1's `preview → confirm → execute` actor loop cannot run.

**Approach:** Add a `usecases/preview.py` `preview_dry_run` that snapshots the live document to a reserved-prefix TempDoc, re-runs a registered mutation tool against that copy through the normal `run_mutation` bracket, measures a before/after `GeometryDiff`, closes the TempDoc, and returns `preview_id` + the diff — proving the live document unchanged by fingerprint. Tighten `contracts/diff.py` so the schema states the shape it returns.

## Boundaries & Constraints

**Always:**
- **The TempDoc is made by `saveCopy` + `document_open`, never `copyObject`.** Measured on 1.1.1: `copyObject` preserves the Name *set* but re-hashes every mapped name (`Face6`: `'#14:1;:G0;XTR;:H778:8,F'` live vs `'#14:1;:G0;XTR;:H8e3:8,F'` on the copy), which makes every element read as re-pointed and would make `tnp_precheck` structurally useless; it also reorders `doc.Objects`. `saveCopy` + `openDocument` preserves object Names 1:1 **in order** and mapped names verbatim, and recomputes clean (`recompute()` returned 0, no `Touched`/`Invalid`). This supersedes `data-contracts-design §8` and `component-design.md:41`, which both specify `copyObject` — record it in the Spec Change Log.
- **The TempDoc file path carries the `FCB_TMP_` prefix, because the reopened `doc.Name` is derived from the file stem.** Measured: `saveCopy` to `<dir>/FCB_TMP_prev_<token>.FCStd` yields `doc.Name == "FCB_TMP_prev_<token>"`. `App.newDocument("FCB_TMP_preview")` cannot be used for this route at all. Reuse the `transaction.temp_snapshot_path` idiom (`transaction.py:85-93`: fresh `mkdtemp` with a reserved prefix, path returned uncreated) rather than inventing a second temp-path scheme.
- **The TempDoc is cleaned by its creator, on every path including failure and exception.** `document_close` (`documents.py:227-239`) drops the handle and every alias, then the temp directory is removed with the `_delete_snapshot` reserved-prefix guard (`transaction.py:96-115`). A leaked TempDoc is adopted by `document_list`'s loop (`documents.py:276-282`) and surfaced to the caller mislabeled `transient: false` — so cleanup is a correctness requirement, not hygiene.
- **The live document is never mutated, and that is proven, not asserted.** Fingerprint the live doc before and after; compare with `contracts.fingerprint.massprops_equal`, never `fingerprints_equal` — `screenshot.py:175` already established that OCCT re-lays-out BRep bytes on first export/render touch, and `saveCopy` is an export touch. Report the digest as `fingerprint_before` (the field is `FingerprintRecord["digest"]`, not `hash`).
- **The op runs on the copy through the same `run_mutation` bracket the live path uses.** The preview does not reimplement mutation; it calls the registered usecase function with the TempDoc handle. A preview whose op fails post-verify is a successful preview reporting a failing diff, never an error.
- **`tnp_precheck` is the `TnpAuditBlock` the copy's own `post_verify` produced, surfaced verbatim.** `UNSUPPORTED` is passed through unchanged — the preview never claims clean (AD-7).
- **Registry lock discipline.** `DocumentRegistry._lock` is a plain non-reentrant `threading.Lock` (`documents.py:100`). Never call a mutation usecase from inside `registry.with_document`; resolve, release, then call. `_ResolvedRegistry` (`transaction.py:69-83`) serves one document and has no `rebind`, so it is not a substitute here.
- **The op table is injected, not imported.** `usecases/` may import stdlib + the six FreeCAD App modules + `contracts`/`usecases` only (`check_imports.py:266-274`); it cannot reach `hosts/tool_catalog.py`. Follow the `RenderPort` precedent: the usecase takes a `Mapping[str, Callable]` parameter and the host builds it. Build it inside `build_inline_handlers`, closed over by the preview spec's `make` — do not widen `HandlerFactory` (`tool_catalog.py:37-39`) and its ~30 spec factories.
- **`debug_exec` is never reachable** as `operation.tool`; the table holds `sketch_*` and `feature_*` only.
- **Every dimension keeps explicit units**, and the render, if any, is capability-gated through the existing `RenderPort` and returns an `OK` envelope when unavailable (`screenshot.py:90-92,429`).

**Block If:**
- The `preview_id` token's shape or lifetime cannot be settled without deciding Story 3.7's confirm-gate validation (whether the token is stateful — a retained TempDoc — or a stateless digest). Prefer the stateless reading: this story mints and returns the id, 3.7 defines what validating it means. Halt only if the stateless reading is provably incompatible with something already landed.
- `document_list`'s adoption of an untracked document cannot be avoided by close-before-return, i.e. a TempDoc must outlive the call.

**Never:**
- Never promote the TempDoc result onto the live document — apply re-runs the op live under AD-5 (Story 3.7).
- Never implement the confirm gate, `confirm.preview_id` validation, elicitation, or `autoApprove` — that is Story 3.7 and DW-85.
- Never register `preview_dry_run` in the read-only profile (`tool_catalog.py:777-793`).
- Never let a mapped-name comparison cross the copy boundary.
- Never emit inline base64 images; renders travel as resource links in the envelope, never inside the diff.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Happy path, additive op | Live body+pad; `{tool: "feature_fillet", args: {...}}` | `OK` envelope with `preview_id`, `expires_at`, and a `GeometryDiff`: `deltas.volume/area` and `bbox`/`com`, `counts.faces/edges/vertices/solids` (measured fillet on a padded square: faces 6→7, edges 12→15, vertices 8→10), `touched`/`new`, `validity.is_valid` true, `tnp_precheck.status` `CLEAN`, `fingerprint_before` = live digest | No error expected |
| Live doc untouched | Any successful preview | Live fingerprint compared before/after by `massprops_equal` — equal; TempDoc closed and its temp dir removed | Inequality is a bug: return non-`OK` and say so |
| Op fails post-verify on the copy | `{tool: "feature_pocket", args}` that breaks the solid | `OK` envelope; diff reports `validity.is_valid` false with `recompute_errors`, or `tnp_precheck.status: FLAGGED`; the preview itself succeeded | The copy's rollback is the copy's business; TempDoc still cleaned |
| Unknown tool name | `{tool: "feature_bogus", args: {}}` | `INVALID_INPUT`, no TempDoc created | `ValidationError` before any file is written |
| Non-mutation tool named | `{tool: "query_shape"}` or `{tool: "debug_exec"}` | `INVALID_INPUT` — the table holds mutation tools only | Same |
| Bad args for a real tool | `{tool: "feature_pad", args: {length: -5}}` | `INVALID_INPUT` from the underlying tool's own validation, surfaced; TempDoc cleaned | The op's `precheck` raises before the bracket opens |
| Element map unavailable | `shim.element_map_available()` false | `tnp_precheck.status: UNSUPPORTED`, no finding claims `PASS`; the rest of the diff is still produced | Never downgraded to `CLEAN` |
| Empty document | Live doc with no shape-bearing objects | Diff with zero-valued deltas and empty count deltas rather than absent keys; `new` names what the op created | No error expected |
| Op deletes an object | An op that removes a node | That Name appears in `deleted`, absent from the after-side counts | No error expected |
| Render requested, unavailable | `render: "auto"` headless with no render capability | `OK`; `render: {available: false, reason: ...}`; the diff is complete without it | Unavailability is not an error |
| Render requested, available, with `view` | `render: "auto"`, `view: {focus: {...}}` | The `view` object is parsed by the existing screenshot path; renders delivered as resource links in the envelope | A malformed `view` is `INVALID_INPUT` (existing fail-closed parse) |
| `render: "off"` | Explicit opt-out | No render attempted; `render: {available: false, reason: "off"}` | No error expected |
| TempDoc creation fails | `saveCopy` raises or the reopened doc will not recompute | Non-`OK` envelope naming the failure; any partial temp dir removed | Never leave a temp dir or an open TempDoc behind |
| Exception mid-preview | Anything raises after the TempDoc opened | TempDoc closed and temp dir removed before the exception surfaces | `finally`-guarded cleanup |

- Given `preview_dry_run` on a build where `shim.element_map_available()` is false, when it returns, then `tnp_precheck.status` is `UNSUPPORTED` and no finding carries `PASS`, and the diff is otherwise complete.
- Given the registered tool inventory, when the read-only profile is built, then `preview_dry_run` is absent from it and `debug_exec` is absent from the preview op table.
- Given a live document holding an object that is already broken before the preview, when a fully successful op is previewed, then `validity.is_valid` and `validity.recompute_clean` are true, the pre-existing breakage appears only in its own `pre_existing_errors` field, and `recompute_errors` does not name an object the op never touched.
- Given an op that fails on the copy (for example `feature_fillet` at a radius the solid cannot take), when the preview returns, then the diff carries the op's terminal status and its `post_verify` explanation text, so no `is_valid: false` is ever reported without a reason.
- Given any preview, when `touched` is read, then it contains only names the op itself reported touching — an origin plane or axis untouched by the op never appears in it.
- Given a document containing a `PartDesign::Plane` or other datum, when an op that really changes area is previewed, then `deltas.area.delta` is the real change and is not cancelled to `0.0` by a datum's `8e+100` area on both sides.
- Given an op that produced no `post_verify` block, when the diff is read on a build where the element map is available, then `tnp_precheck.status` is `UNSUPPORTED` rather than `CLEAN`.
- Given `preview_dry_run` invoked through a host (not by a test injecting a sink), when it completes, then an audit record with `event: "preview"` has been written.

## Spec Change Log

**1. The diff needs a rule for WHICH objects it measures, and the obvious rule double-counts every PartDesign chain.** The spec fixes the expected numbers ("faces 6→7, edges 12→15, vertices 8→10") but never says what the diff sums over, and the naive reading — every shape-bearing object — produces the wrong ones. Measured on a 10×10×5 pad after a 1 mm fillet on `Edge1`:

```
metric set                       objects            volume     F   E   V   S
every shape-bearing object       Pad, Fillet        998.927    13  27  18  2   <- wrong
                                 (+ Body 498.927, + 3 origin planes at area 8e+100 each)
shape-bearing minus peer-linked  Fillet             498.927     7  15  10  1   <- the spec's numbers
live pad before                  Pad                500.000     6  12   8  1
```

Three distinct over-counts stack. (a) `PartDesign::Fillet` does not replace its `Pad`: both remain in `doc.Objects` and both keep a live `Shape`, so a sum reports 500 + 498.927. (b) `PartDesign::Body` is a container echoing its own tip, so it adds the tip's volume a third time. (c) An origin plane reports `Shape.Area == 8e+100` (measured on all three of `XY_Plane`/`XZ_Plane`/`YZ_Plane`), which would swamp every area delta. `usecases/preview.py:61` `metric_objects` therefore takes the shape-bearing, non-construction candidates and drops any that another candidate links to — `PartDesign::Feature.BaseFeature` is `App::PropertyLink` (`docs/references/FreeCAD/src/Mod/PartDesign/App/Feature.h:67`), `Part::Boolean.Base`/`.Tool` likewise (`FeaturePartBoolean.h:46-47`), `FeatureDressUp.Base` is `App::PropertyLinkSub` (`FeatureDressUp.h:45`), and `Part::MultiFuse.Shapes` is `App::PropertyLinkList` — so reading `InList` catches all four property shapes without enumerating any of them. Verified across six documents: pad-only `['Pad']`, pad+fillet `['Fillet']`, a three-deep chain `['Fillet2']`, two loose boxes `['Box','Box2']`, after a `Part::Cut` `['Cut']`, and two independent bodies `['PadA','PadB']`. Known-bad state avoided: a diff that reports a 1 mm fillet as *adding* 498.927 mm³ and seven faces. **`Visibility` is not a usable filter for this** and was rejected on measurement: the fillet sets `Pad.Visibility = False` (so a visibility filter would work by accident there), but `Part::Cut` leaves `Box.Visibility == True` while consuming it, so the same filter would double-count every boolean.

**2. `tnp_precheck` is typed as `contracts.mutation.TnpAuditBlock` itself, not a structurally-equal copy.** The spec says the block is surfaced verbatim; `contracts/diff.py` now imports it rather than redeclaring the same three fields, so the diff's `$def` and the mutation block's `$def` are one type and cannot drift. Consequence in the emitted schema: `tnp_precheck.status` is `{"enum": ["CLEAN","FLAGGED","UNSUPPORTED"]}` where it was `{"type": "object"}`, and `findings` items `$ref` `RefFinding`. This is what makes the AD-7 "never claims clean" rule checkable on the wire instead of only in code. `contracts/` stays stdlib-only and acyclic (`diff.py` -> `mutation.py` -> `fingerprint.py`/`status.py`); `check_imports OK`.

**3. `query_mass_properties` keeps its `None`-for-non-solid wire shape; only the reader underneath it is shared.** The spec asks to "settle what a non-solid contributes where `query_mass_properties` returns `None`". Settled as two different jobs with one measurement: `queries.shape_metrics` (`queries.py:119`) returns plain summable floats — `volume: 0.0` and a bbox-centre `com` for a non-solid, because a `ScalarDelta` carries four non-optional floats and a diff that turned a solid into a shell must still produce a number. `query_mass_properties` (`:425`) calls it and then re-applies its own `None` mapping, so its published envelope is byte-for-byte what it was apart from one added key. The one wire change is additive: `counts` gains `vertices` alongside `faces`/`edges`/`solids`, which the diff requires and no consumer pins negatively (its schema is not generated; `tests/infc/test_query_tools.py` asserts the analytic volume, not the counts key set).

**3a. Extracting the shared reader silently changed `query_mass_properties`' output for a compound of solids, and the shared reader needed a third flag to avoid it.** Caught while re-reading the refactor diff, before it shipped. The original code computed `com = getattr(shape, "CenterOfMass", None) if is_solid else None` and emitted `"com": None` when `com is None` — two distinct reasons collapsed into one branch. The first cut of the refactor rewrote the branch as `if not is_solid`, which is *not* the same predicate: a solid can lack `CenterOfMass`. Measured on 1.1.1:

```
Part.makeBox(2,3,4)                       len(Solids)=1  hasattr CenterOfMass=True   Vector (1.0, 1.5, 2.0)
Part.makeCompound([box, box@(5,0,0)])     len(Solids)=2  hasattr CenterOfMass=False  -> AttributeError
Part.makeBox(1,1,1).Shells[0]             len(Solids)=0  hasattr CenterOfMass=True   Vector (0.5, 0.5, 0.5)
Part.Vertex(...)                          len(Solids)=0  hasattr CenterOfMass=False
```

So a `Part::Feature` holding a compound of two solids would have flipped from `"com": null` to a bounding-box centre presented as a centre of mass — the exact substitution the original comment (`queries.py`, "unavailable on some shape types, e.g. Part.Compound") exists to prevent, on a shipped read-only tool, with no test covering it. `shape_metrics` now returns `com_readable` alongside `solid`, `query_mass_properties` keys its `None` on `com_readable`, and the preview keys its volume-weighted centroid on `solid` (a compound of solids has real volume, and the bbox centre is the only number available for it — acceptable inside a diff, not acceptable as a published centre of mass). Falsifiability confirmed by mutation: reverting the branch to `if not is_solid` produces exactly 1 failure, `SharedShapeMetricsTest.test_query_mass_properties_still_reports_null_com_for_a_compound`. Known-bad state avoided: an area/length or bbox centroid published as volumetric mass on the existing read-only surface.

**4. `preview_id` and `expires_at` sit on the envelope's structured content beside the diff, not on the diff.** The spec left this open ("on the diff or on the envelope's structured content beside it"). Chosen as siblings, matching `mcp-tools-design §3.8`, whose `outputSchema-result` lists `preview_id`, `diff`, `renders` and `expires_at` at the same level. **11. The diff's five report fields were underspecified, and each one was filled in by a plausible-but-wrong rule. Amended here; this entry is binding on the re-derivation.**

*Triggering findings:* the six `bad_spec` findings in the review pass below. All five defects share one root cause — the spec named the fields (`validity`, `tnp_precheck`, `touched`/`new`/`deleted`, the metric set) and said `validity`/`tnp_precheck` were "projections", but never said *of what*, so the implementation supplied its own answer for each and every answer over-reported.

*What is amended, as rules the re-derivation must satisfy:*

- **`validity` is a projection of the op's own `post_verify` block and nothing else.** `is_valid` and `recompute_clean` are exactly `post_verify["is_valid"]` / `post_verify["recompute_clean"]`; no independent document sweep may weaken them. Breakage that predates the preview belongs in a separately named field (`pre_existing_errors`) so the reader can tell "your op breaks this" from "this was already broken". Known-bad state to avoid: a whole-document error sweep AND-ed into the op's verdict — measured, one unrelated broken `Part::Extrusion` flips a fully successful fillet to `is_valid: false` and names an object the op never touched. `recompute_errors` stays, but it carries the errors `post_verify` attributes to the op.
- **The op's terminal status and explanation reach the caller.** The diff carries the op envelope's `status` and its `post_verify["explanation"]`. Measured: `feature_fillet` at radius 500 returns `RECOMPUTE_ERROR` with `explanation: "recompute left 1 object(s) invalid: Fillet: BRep_API: command not done"`, and none of it currently survives. Known-bad state to avoid: `is_valid: false` with an empty `recompute_errors` and no reason anywhere — a preview that says "no" without saying why is not evidence, which is the whole point of the story.
- **`touched` is what the op reported touching, intersected with what still exists.** `run_mutation`'s `op` callback returns exactly this list (`transaction.py:459`) and it reaches the preview through `mutation["touched"]`. `new` and `deleted` stay as the name-set difference, which is correct for them. Known-bad state to avoid: `sorted(names_before & names_after)` — the set of objects that were neither created nor deleted, measured as 11 names including `X_Axis`, `XY_Plane` and `Origin001` after a single fillet.
- **The metric-object rule is stated positively and is not a type deny-list.** An object is measured when it bears a non-null shape, nothing else in the candidate set links to it, and it is a model result rather than construction geometry. Known-bad state to avoid: enumerating construction types by prefix — the landed list omitted `PartDesign::Plane`/`Line`/`Point`/`CoordinateSystem`, and a `PartDesign::Plane` datum contributes `area 8e+100` to both sides so the real area delta cancels to `0.0`. Prefer a positive test (a datum has no solid, no face area a model reports, and is a `App::GeoFeature` attachment target) over a growing list of names; if a deny-list is unavoidable, it must be justified by measurement and its incompleteness treated as the defect it is.
- **A TNP audit that did not run is never `CLEAN`.** When the op produced no `post_verify`, the pre-check status is `UNSUPPORTED` regardless of whether the element map is available — "we did not look" and "we looked and saw nothing wrong" are different answers and AD-7 forbids collapsing them. Known-bad state to avoid: `"UNSUPPORTED" if not shim.element_map_available() else "CLEAN"`, which reports clean for an ungraded op on every CI leg (where the map is always available).
- **The preview audit record is written on the production path, not only when a test injects a sink.** Both hosts gate auditing on `method.mutating or name == "debug_exec"` (`mcp_server.py:178`, `rpc_listener.py:320`), and `preview_dry_run` is `mutating=False`, so the `audit_event="preview"` field currently does nothing; the spec's factory also never passes `audit_sink`. Either the host gate admits `audit_event == "preview"` or the factory passes the sink — both ends must be wired, and a test must fail if either is unwired. Known-bad state to avoid: an `AuditTest` that passes by calling the usecase directly with a sink, while production writes zero preview records.

## Design Notes

**Why `saveCopy` + `openDocument` rather than `copyObject`.** Measured on FreeCAD 1.1.1, same session, same source body:

```
                 ElementMapSize   getElementMappedName("Face6")
live                   30         '#14:1;:G0;XTR;:H778:8,F'
copyObject copy        30         '#14:1;:G0;XTR;:H8e3:8,F'    <- :H tail rehashed
saveCopy + reopen      30         '#14:1;:G0;XTR;:H778:8,F'    <- verbatim
doc.Objects order:  copyObject reorders;  reopen is 1:1 in order
reopened doc.recompute() -> 0 recomputed, no Touched/Invalid
```

The `:Hxxxx` component is a per-document string-hasher index, not geometry. Under `copyObject` every entry's mapped name differs, so a Layer-1 diff on the copy would report `REPOINTED` for every reference — `tnp_precheck` would be structurally incapable of reporting `CLEAN`. The design docs specify `copyObject` (`data-contracts-design §8`, `component-design.md:41`); they were written before this was measured.

**`fingerprints_equal` is the wrong oracle for the live-doc proof.** `saveCopy` is an export touch, and OCCT re-lays-out BRep bytes on first export, so a digest comparison would report a mutation that did not happen. `massprops_equal` (`contracts/fingerprint.py`) exists for exactly this and is what `screenshot.py:175` uses after rendering. `fingerprint_before` in the diff is still the digest — reporting it and comparing on it are different jobs.

**`validity` and `tnp_precheck` are projections, not a second measurement.** The copy's `post_verify` already produced `{recompute_clean, is_valid, fully_constrained, tnp_audit}` (`transaction.py:191-197`). `validity` is `{is_valid, recompute_clean, recompute_errors}` and `tnp_precheck` is the `TnpAuditBlock` verbatim. Computing either independently would let the preview and the eventual live mutation disagree about the same op.

**Two documents, one non-reentrant lock.** `registry.with_document` holds `threading.Lock` for the whole callback (`documents.py:121-125`), so resolving the live doc and then calling `features.feature_pad(registry, doc=temp_handle, ...)` inside that callback self-deadlocks regardless of the two handles naming different documents. Resolve, release, then call. `_ResolvedRegistry` does not help: it serves one bound document and ignores the handle argument, and it has no `rebind`, which `_feature_mutation` calls at `features.py:383` under a `finally` whose `except Exception: pass` would silently swallow the failure.

**The op table entries are bare usecase functions.** `_sketch_method`/`_feature_method` build handlers as `lambda **p: fn(doc_registry, **p)` (`tool_catalog.py:300-301,460-461`) with the live registry closed over. The preview needs to supply its own registry and TempDoc handle at call time, so it needs `sketches.sketch_create` / `features.feature_pad` themselves, not the wired handlers. Going through `adapters/rpc_dispatch.MethodRegistry` is doubly wrong: it is an outward import, and its handlers are marshal-wrapped, so calling one from inside an already-marshaled dispatch re-enters the Qt main-thread marshal (`tool_catalog.py:8-12`).

**Counts the diff needs that no existing reader produces.** `query_mass_properties` reports `faces/edges/solids` and never reads `shape.Vertexes` (`queries.py:425-429`); it also returns `volume: None` and `com: None` for non-solids (`:404,408,418`), which a `ScalarDelta` — four non-optional floats — cannot represent for a preview that turns a solid into a shell. Measured reference values on a 10×10×5 padded square: `Vertexes 8, Edges 12, Faces 6, Solids 1, Volume 500.0`; after a 1 mm fillet on one edge: `Vertexes 10, Edges 15, Faces 7, Solids 1`.

**Document Name is not the string you passed.** `App.newDocument("FCB_TMP_preview")` a second time yields `Name == "FCB_TMP_preview1"` (silent numeric suffix, no error), and non-alphanumerics are sanitized out of `Name` while `Label` keeps them. On the `saveCopy` route the reopened `Name` is the file stem, so the reserved prefix belongs in the filename. Always read `doc.Name` back rather than assuming it.

**FreeCAD has no `Transient` flag.** `hasattr(doc, "Transient")` is `False`; the real property is `Temporary`, read-only and settable only via `newDocument(name, label, hidden, temp)` (`Document.pyi:89`). `DocHandle.transient` is registry-side bookkeeping with no FreeCAD counterpart — note that `document_open` sets `_transient = False` (`documents.py:202`), so a TempDoc opened this way is not marked transient and `document_save` on its handle would write the temp file. Cleanup, not the flag, is what protects the invariant.
