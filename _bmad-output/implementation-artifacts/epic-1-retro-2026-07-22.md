## 2. What Went Well

- **The review layer caught real defects on every story.** Adversarial + edge-case + verification-gap hunters found genuine bugs, not nits: 1-3 self-read/oracle mislabels; 1-4 exec-gate placement + audit-boundary; 1-7 unguarded self-read leg (crash→FAIL), 3MF metadata false-alarm coupling, mislabeled STL winding check; 1-8 double-marshal, malformed-frame isolation, **pre-auth version disclosure**; 1-10 stored-verdict-must-be-re-derived, bool-as-sensitivity rejection, red-CI-leg-not-masked. This is AD-13/AD-17 "never grade yourself" working in practice.
- **Honest-fail discipline held.** The G0 gate runner fails against a stub (AD-19) and is double-protected (test + CI hard-fail on a green stub). The gate itself applies the re-derive-not-trust rule to its own evidence.
- **Independent-oracle verification is real.** Golden values hand-computed (not captured), fingerprint serializer-tagged, export oracles cross-checked with disagreement = FAIL.
- **The deferred-work ledger worked as designed.** ~35 incidental findings captured with evidence + a resolution pointer instead of scope-creeping the current story. Nearly all are "not reachable in Phase 0, revisit when X lands" — correct triage.
- **Zero escalations across 10 stories.** The loop ran autonomously end-to-end once the operational frictions (below) were resolved.

## 3. Challenges

- **Session-timeout mid-story required manual recovery twice (1-3, 1-9).** Both are large stories that ran multiple review loops and hit the 90-minute `session_timeout_min` at the finalize step. Because `[scm] rollback_on_failure = false`, the tree was left dirty and the run paused for manual disposition each time. Recovery each time: verify the work (external suites green), confirm completeness, finalize spec + commit + patch engine state + resume. Real cost: operator intervention per timeout.
- **The global "never auto-commit" rule halted every story's commit.** The spawned dev sessions inherited the operator's global CLAUDE.md rule and paused to ask for commit approval on each story. Resolved mid-epic by adding a scoped project-CLAUDE.md carve-out (bmad-loop per-story commit is pre-approved). After that, sessions self-committed.
- **Comment discipline drifted early.** Stories 1-1/1-2 wrote docstrings dense with AD/§ spec-traceability tags. A CLAUDE.md rule ("comments are pure code docs, artifacts hold latest state not history") was added mid-epic and a bulk cleanup applied (commit `75da922`, ~28 files). Later stories honored the rule automatically.
- **Two validator fault suites are statistically thin.** Export validators shipped at n=2/n=3 (vs NFR2's ≥10), so the ≥95%/≤5% gate passes but the Wilson lower bound is weak (0.34–0.44).
- **A few CI-gate enforcement gaps are known but unclosed.** `check_imports.py` does not yet ban `pivy.coin.SoOffscreenRenderer`, `FreeCAD.ActiveDocument`-as-target (AD-20), or top-level FreeCAD/Qt imports in usecases/marshal — each enforced only by review today.

## 4. Key Lessons

1. **Big multi-loop stories will hit the session-timeout at finalize.** The pattern is consistent (1-3, 1-9). The interrupted work was complete-and-correct both times — the timeout struck at the commit/finalize step, not mid-implementation. Enabling `[scm] rollback_on_failure` would make timeouts self-clean, but at the cost of discarding good work; the current keep-and-finalize recovery preserved it. Prefer keeping the manual-recovery-preserves-work posture, but shrink the trigger (see actions).
2. **Operator global rules leak into spawned sessions.** Any always-on CLAUDE.md rule (auto-commit ban, comment style) governs the loop's dev/review sessions. Establish project carve-outs / rules *before* starting a long autonomous run, not mid-flight.
3. **The review layer is the epic's quality engine.** Every story's real bugs came from the hunters, not the implementer. The re-derive-not-trust principle (verdicts, oracles, evidence) repeatedly caught self-grading holes. Keep the review layer non-negotiable.
4. **"Not reachable in Phase 0, revisit when X lands" is the right deferral.** The ledger's forward-looking discipline kept stories scoped. But forward-looking debt must actually be scheduled — several items name specific future stories (1.6/1.8/Phase 2/3) as their resolution point.
