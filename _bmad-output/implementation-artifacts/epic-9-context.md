# Epic 9 Context: Viewport & Render Correctness

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Epic 9 corrects four defects in behaviour that already shipped: the viewport framing read and the auto-fit tool, and the constructed-scene render. When the bridge says the human can see the model, the human must actually be able to see it; when it cannot, the agent must get a measured number it can act on instead of a success it must not trust. A render from any named camera must show the part instead of a white rectangle. Every temp file the bridge writes must land where the bridge's own cleanup can find it. Three of the four defects are the architecture already being right and the code not matching it; the fourth is a hygiene contract the render path never joined. Every defect was reproduced live against FreeCAD 1.1.1 (GUI addon + external proxy host) before it was written down.

## Stories

- Story 9.1: One Projection for Fit and Verdict, and a Fit That Verifies Itself
- Story 9.2: A Wrong-Document Guard That Can Actually Fire
- Story 9.3: Every Camera Renders a Visible Part
- Story 9.4: Temp Files the Sweep Can See

## Requirements & Constraints

- **Correction work, not a phase boundary.** This epic opens no gate and reopens no closed epic. There is no gate-exit story. A passed gate stays closed; these fixes carry forward.
- **Acceptance for the epic:** the four reproducers recorded in the UAT run (`tests/uat/run/2026-09-13-02/bugs.md`) re-run clean, each against the regression fixture its own story adds.
- **The fit frames with the same measurement it grades itself by.** One shared corner-projection routine serves both the framing verdict and the fit factor; no second analytic estimate of the same quantity may remain. `fitted: true` may not be reported when the post-fit projection says the model does not fit.
- **The wrong-document refusal must be able to fire.** A fit aimed at a document other than the one on screen is refused, naming both documents, and moves no camera.
- **Every named camera plus `custom` must render a shaded face.** Verified by a two-sided tone band with a sample-count floor, run across all cameras — not `iso` alone.
- **Every temp file the bridge writes is created inside the session workdir**, so the session-start sweep can see it. The sweep's scope stays exactly the session workdir and never scans the OS temp directory.
- A fifth reported item (`export_*` "creates missing parent directories") was closed as invalid — no story. A missing parent returning `RECOMPUTE_ERROR` instead of `INVALID_INPUT` is deferred work, not a fix.
- The render is a validator like any other: its defect cases belong in the fault-injection suite (a planted all-white render must be caught mechanically), not only in a human spot-check. Validators must prove their sensitivity/false-alarm bar before their verdicts are citable.

## Technical Decisions

**Framing verdict is an exact projection test (AD-30).** "Beyond the viewport" means: project the 8 corners of the union bounding box of the visible shape-bearing objects through `View3DInventor.getPointOnViewport` and test containment against `getSize()`. `fits` is false iff any corner falls outside the viewport rectangle. The *fit* and the *verdict* share one corner-projection routine — an analytic silhouette estimate of the same quantity is banned, because a second cheaper approximation is the defect, not an optimization. The measured error of the shipped estimate runs 1.155 (cube) through 0.856 (long bar), so compact and near-cubic parts clip while elongated ones pass. Because `getPointOnViewport` projects through the *current* camera, the factor cannot come from a post-fit projection; the fit is therefore **three passes inside one animation-suspended block** — measure the pre-fit extent, `fitAll(factor)` scaling that extent to the fill fraction on the binding axis, then re-project through the now-written camera to verify. Animation suspension is a **precondition**, not best-effort: with animation on both camera writes land after the call returns and pass 3 silently re-reads the pre-fit camera. A fit that cannot suspend animation cannot verify itself. The binding axis is the framing verdict's axis (larger of the two `extent / viewport_extent` quotients), not `fitAll`'s sphere radius — they differ on any non-cubic part. Use `getPointOnViewport`, never the `getPointOnScreen` alias (same C++ function; the name invites bogus DPI offsets). Three source-verified hazards must be handled: the projection does not clamp off-screen corners (that is what makes containment testable — do not "fix" it); the `SbVec2s` return can overflow `short` and wrap sign, so an implausible magnitude is treated as outside and never trusted; Y is inverted relative to Qt, harmless for containment but any reported pixel coordinate must state its convention. "Visible shape-bearing" reuses the one existing default-render predicate — framing and render may never disagree about what is on screen. A child whose own visibility flag is true inside a hidden container counts as visible to both; that is a stated limitation, and a fix must land in both places or it recreates the divergence.

**Live viewport access is a host capability (AD-29).** Reading or writing the live GUI camera happens only behind `ViewportPort`, declared in contracts beside `RenderPort` and implemented in the GUI addon host. It is **not** an extension of `RenderPort` — extending the existing offscreen renderer would put live-camera code in `adapters/` and force a second Qt exemption. Offscreen-render availability and live-viewport availability are separate predicates: headless can render offscreen and has no view. The port carries a third method, **`showing_document_name() -> str | None`**, beside `available()` and `view()`. It is session-wide and takes **no document** — it names the one document on screen. It exists because `view(document)` cannot answer the question: the view is resolved through the handle's own name, so any guard comparing that view's document against the target compares a name with itself and can never fire. The on-screen name must therefore come from a source independent of the target handle — the focused Qt MDI sub-window inside the GUI addon host. **`None` is not a refusal**: an unreadable name is no evidence of a mismatch, so the fit proceeds. `None` deliberately conflates "no viewport" with "name unreadable" and carries **no reason string**, because both are treated identically and a reason would invite a caller to branch on a distinction with no consequence. Hosts with no viewport inject `None` and the usecase reports the capability unavailable. Adding the third method requires correcting the port docstring's "Both answers are per document" sentence, which the new method falsifies. A targeted document whose view exists but is not the focused one still gets its own framing verdict — `showing_document_name()` governs the **fit refusal only**, never the verdict's target.

**`view_fit_viewport` is a view-only, audited op (AD-31).** It changes no geometry and no fingerprint, so it is confirm-exempt and follows the shipped lifecycle-op shape: `mutating=True`, **no `confirm` property in its input schema**, and no routing through the mutation wrappers or `run_mutation` (routing it there would make it demand a preview token). The confirm gate is a call site, not schema-driven. Declaring it `mutating=False` would silently drop it from the audit log. Its audit record carries the **prior camera** verbatim, in its own optional field — never folded into the params digest (a digest is irreversible; reversibility is the point) and never into the geometry fingerprint. In multi-client mode the actor names the issuing session, or racing fits cannot be ordered. **`fitted: true` is a measurement, never "the call ran"**: it requires the post-fit re-projection to return `fits: true`; a contradiction returns `SPEC_FAILED`. **That post-fit `SPEC_FAILED` carries its `framing` block** — the single carve-out in the omission rule below. A fit that cannot converge is a failure, not a retry loop: a factor computed from geometry rather than measured feedback cannot improve by repetition, so the tool reports the honest failure on the first contradiction rather than inviting a re-fit. The tool requires an explicit `doc` handle; a handle that does not name the document the live viewport is showing returns `INVALID_INPUT` naming both documents — never a silent redirect. It must not fit the active document instead, and must not activate the named document (raising another document's view is exactly the unrequested GUI change the camera-ownership rule prevents). `FreeCADGui.ActiveDocument` stays banned in **every** ring including `hosts/` — the import checker applies it with no layer filter, and the wrong-document bug is precisely the implicit-target defect the ban exists to prevent, so the enforcer is not relaxed to make the fix easier. On a quarantined document the fit is refused. The tool is not in the read-only assistant allow-list.

**Framing is computed on change, not per call (AD-32).** The verdict is recomputed when geometry or visibility changed since the last check, or on explicit opt-in; a repeated pure query reuses the cache. The warning rides a structured `framing` block as an optional top-level envelope key (not inside `structured_content`), and the human-readable sentence is rendered **from that block by one shared helper** in contracts — never appended by each tool's own summary. Fields are fixed: `fits: bool | None` (`None` only when the verdict could not be computed, never a guess); `ratio: float | None` computed from the 2D axis-aligned hull of the 8 projected corners on the binding axis, where `1.0` exactly fills and `> 1.0` overflows — and **`ratio` is `None` while `fits` is `false`** if any corner was discarded as an implausible magnitude (stated constant: any coordinate exceeding 4× the corresponding viewport dimension), because fabricating a fraction would report a wildly wrong camera as a hair's-breadth miss; `checked: "computed" | "cached" | "unavailable"`; `stale_reason: str | None`. **Staleness is not camera-only** — the cache key is the four-tuple `(fingerprint, camera_string, viewport_size, active_view_id)`, because a window resize or splitter drag changes the viewport size while camera and geometry are untouched, and a cached `fits:true` would then describe a viewport that now clips. A cached verdict whose key differs in any component is reported `checked:"cached"` with the differing component named. If even that cheap GUI read is refused, the verdict is reported cached with an explicit reason — **never as fresh**. The verdict describes the state **after** the call's own effect, measured once the recompute has settled, and the read sits **outside** the mutation bracket, after commit (inside it would measure uncommitted geometry, leak abandoned state on rollback paths, and lengthen the window in which the Qt loop is blocked). **On any non-`OK` terminal status the block is OMITTED — with exactly one carve-out: `view_fit_viewport`'s own post-fit `SPEC_FAILED` carries its block**, because that verdict is freshly `"computed"`, is the *cause* of the status rather than a leftover, and `ratio` lives nowhere else in the contract. The carve-out extends to no other tool, no other status, and not to the fit's own no-viewport or refused-fit outcomes, which measured nothing. The envelope wrapper short-circuits on non-`OK` today, so the carve-out is a deliberate change at that site. The ratio must **not** be hand-written into the prose reason. Three states discriminated by `checked`, never by absence: no viewport for this document (including a GUI document with no open 3D view) → block omitted; projection attempted and failed → block present with `fits:null` and `checked:"unavailable"` and the failure named; projection succeeded → real bool with `"computed"` or `"cached"`. A quarantined document is never projected. The verdict is always about the **targeted** document, never whichever happens to be on screen.

**A render must be distinguishable from an empty scene, on every camera (AD-34).** The lighting rig is a stated invariant, not per-implementer tuning: every named camera must render a face tone separable from the background. A single directional light aimed **along** the view axis does not satisfy this — for an axis-aligned camera the visible face's normal is exactly anti-parallel, the diffuse term degenerates, and only the ambient term remains, saturating the near-white default material to pure white. The rig therefore offsets the headlight off the pure view axis (FreeCAD's own viewport headlight is not exactly camera-parallel, which is why the live viewport shades these views correctly) or adds a second fill light at an angle. **The acceptance test is two-sided, and one-sidedness is how the defect shipped**: the existing rig's stated purpose was "so no face renders black" — it closed the black end and opened the white end, and a test asserting only "not black" passes the current defect while a test asserting only "not white" would re-admit the original. The check runs across all named cameras plus `custom`. The band is a stated constant: mean interior tone (a) differs from the background tone by **≥ 24/255 on at least one channel** *and* (b) lies within **`[20, 235]` on every channel**. Interior sampling excludes the outer 10 % of the span on each axis and requires **≥ 500 interior samples** — the defect yielded only ~138, all anti-aliased edge pixels, so the sample floor is part of the assertion, not a harness detail. Measured defect: `iso` fills `rgb(159,164,169)`, while `front`/`top`/`right`/`back` render the face at `rgb(255,255,255)`, identical to the background; orientation is correct in all of them, so orientation assertions pass while the image carries no shape information beyond its outline. The fix must not brighten `iso`, which already matches the live viewport. This is a recorded divergence from the design doc, which still specifies a bare unaimed light with no ambient — that line must be updated in the same change, because the shipped divergence was never written down and so was never reviewed.

**Data & artifact locations (AD-25).** Every file the bridge writes lives under a session-scoped workdir owned by the documents use case (`snap/`, `exports/`, `audit.log`, `tmp/`). The bridge never writes into the user's document directory except through an explicit save/export call carrying an operator-supplied path. **Every temp file goes inside the session workdir — the sweep never reaches outside it.** Render outputs and fingerprint temporaries currently call the temp-file API with no `dir=` argument and land in the OS temp directory, outside the scope this decision gives the sweep; that is why 392 of them accumulated across already-exited sessions. The fix is passing `dir=<workdir>/tmp` at the creation sites, **not** a sweep that scans the OS temp directory: on a shared or multi-user host that directory is another session's territory, and deleting from it would break the guarantee that a caller may still be reading a returned link. Pre-existing strays there are a one-time operator cleanup, never a bridge responsibility. **The reserved `FCB_TMP_` prefix marks FILES only** — several reserved names identify **in-memory FreeCAD documents** (previous-state, VarSet probe, PartDesign probe, type probe), which are released by closing the document and must never be handed to `unlink`; a sweep written against "every reserved prefix" fails on the first probe document it meets. Because a render link may still be being read when the call returns, the sweep runs at **session start**, never as an immediate unlink. **A cleanup failure may not leave a silently-orphaned directory**: the snapshot delete removes the files then swallows the directory-removal error, which is why empty snapshot directories survive despite the deletion contract. A swallowed cleanup error must still leave the artifact sweepable at the next session start, and the failure must be surfaced (logged) rather than discarded so the next occurrence is diagnosable. The surviving directories *correlate* with the snapshot-restore path, where the document is reopened and holds the file open, but that cause is **indicated and unverified** — do not encode it as fact without reproducing it.

## Cross-Story Dependencies

- **9.1 → 9.2 are ordered**: both edit the same fit use-case module. 9.1 lands the shared projection, the three-pass fit, and the post-fit verdict; 9.2 then replaces the tautological guard.
- **9.3 and 9.4 touch disjoint files** and are parallel-eligible with either of the above.
- **DR-3 is not independently shippable** — the `framing`-carrying `SPEC_FAILED` lands with 9.1, because it is the failure envelope 9.1 introduces.
- 9.1 and 9.2 depend on the shipped Epic 8 surface (framing read, fit tool, `ViewportPort`) and on the corner-projection routine that already exists in the framing use case; 9.2 additionally depends on a new `ViewportPort` method implemented in the GUI addon host.
- 9.3 depends on the render probe adapter and on the screenshot use case; its regression case must also join the render fault-injection suite.
- 9.4 depends on the session workdir owned by the documents use case and on the transaction snapshot-deletion path.
- Documentation drift is in scope alongside the code: the design docs predate the viewport/framing amendment and still describe the superseded lighting rig, and the framing/fit sections were never folded down. Update them in the same change rather than leaving the next reader designing against a stale rig.
- Still open and to be calibrated during implementation: the **near-miss tolerance** (how many pixels outside still reads as fitted). The previously published band must be re-derived from the fixed implementation — under a projection-based factor every test shape lands at a single value, where the old estimate spread them widely. A hair-trigger warning on every call is noise.
