## Intent

**Problem:** The bridge exposes no render tool. An MCP client (or the human it serves) cannot get visual context of a document, and there is no capability probe telling it whether a GL render context even exists. FR3 requires view-controlled screenshots — include/exclude, per-object transparency/color, focus-on-element framing, highlight, camera presets — that render a *constructed* scene and NEVER mutate the document or the user's viewport.

**Approach:** Add a read-only `query_screenshot` tool (mcp-tools §3.9) backed by a render capability ladder in `adapters/render_probe.py` (the AD-1 render carve-out) and a `RenderPort` injected at host startup so `usecases/` stays Gui-free. The usecase assembles a per-call scene spec (which objects, style overrides, camera orientation, focus bbox) from the `view` options and hands it to the port; the port builds its own Coin scene graph via `FreeCADGui.subgraphFromObject`, renders offscreen with `FreeCADGui.SoQtOffscreenRenderer`, and writes a PNG ≤1024 px returned as an `ImageRef` `resource_link` with `audience:["user"]`. When the ladder reports `none`, the tool returns `render.available: false` with a reason — never a hard failure. A document fingerprint taken before and after the render must match (nothing mutated).

## Boundaries & Constraints

**Always:**
- `query_screenshot` is **read-only / non-mutating**: it constructs its own scene, never touches `Visibility`, document objects, transactions, or the user's live viewport. Document `fingerprint()` before == after (assert this in the usecase and in tests).
- Ring/import discipline: `usecases/` imports stdlib + FreeCAD App API only — **no `FreeCADGui`, no `pivy`/`coin`, no Qt**. All Gui/Coin imports live in `adapters/render_probe.py` (the named AD-1 carve-out) and `hosts/**` only, imported **inside functions**. `adapters/__init__.py`/`hosts/__init__.py` stay byte-empty. `check_imports.py` MUST stay green.
- Render ladder (detection-mcp-freecad §6): (1) `FreeCAD.GuiUp` → `gui_constructed`; (2) else lazy `import FreeCADGui`, **immediately** `FreeCADGui.setupWithoutGUI()` (mandatory ordering), ensure a `QGuiApplication`, 8×8 probe render → `offscreen`; (3) import/GL/probe failure → `none`. Result cached once per process. **`OffscreenRenderPort.render` gates its `setupWithoutGUI()` on the ladder mode** — it calls `setupWithoutGUI()` only in `offscreen` mode, never in `gui_constructed` (a live GUI process must not be torn into no-GUI mode to take a screenshot).
- Renderer MUST use `FreeCADGui.SoQtOffscreenRenderer` — **never** raw `pivy.coin.SoOffscreenRenderer` (banned, decision 003 / #13356). Scene built from `FreeCADGui.subgraphFromObject(obj)` per object; include/exclude = simply add / don't add the subgraph; style overrides wrap a styled object's subgraph in its own `SoSeparator` with a prepended `SoMaterial`; highlight = a distinct accent material.
- Output PNG ≤1024 px each dimension (`width`/`height` default 800×600, hard-capped 1024). `ImageRef` = `{kind:"resource_link", uri:<path>, mime_type:"image/png", audience:["user"]}`; never inline base64 (AD-10 token budget). PNG written to a caller-independent temp path.
- **PNG lifecycle is owned by the tool.** The `render_port.render(...)` call is wrapped so that on ANY non-OK outcome (fingerprint mismatch, `render()` raising) the just-created temp file is removed before the error propagates — no path orphans a file. On success, verify a **non-empty** PNG was actually written (file exists and size > 0) before returning it; a missing/0-byte file is a failure (remove it, return `RECOMPUTE_ERROR`), never an `OK` with a dead `resource_link`.
- **Response echo must match what was rendered.** `highlight` accent is applied at **whole-object** granularity in this story; a `highlight` selector that names a sub-element highlights the whole object. Never echo an effect that was not applied (do not report a sub-element highlight/focus accent the renderer skipped). `focused_on` echoes the focus selector **only to the granularity that was actually framed**: if the focus target could not be sub-framed (object not in the rendered set, no `Shape`, or a `mapped_name`/sub-element that did not resolve), the camera falls back to whole-scene/whole-object and the echo drops the sub-element part (echo object-only, never a sub-element the camera did not frame). A `focus`/`highlight` selector MUST NOT carry both a `mapped_name` and an `element_type`/`index` (reject `INVALID_INPUT`); a non-string `mapped_name` is `INVALID_INPUT` (fail-closed, not silently dropped).
- **Input validation is coherent and fail-closed.** Every object name in `include`/`exclude`/`styles`/a selector MUST exist in the document, else `INVALID_INPUT` (no silent drop). `color`/`transparency`/`custom_orientation` coercion is wrapped so a bad value is `INVALID_INPUT`, never a bare `ValueError`→`RECOMPUTE_ERROR`. A partial sub-element selector (`element_type` xor `index`) is rejected `INVALID_INPUT`. A degenerate `custom_orientation` (zero-norm or non-finite) is rejected `INVALID_INPUT`. The `view` object and `focus`/`highlight` JSON schemas carry `additionalProperties:false` + inner selector properties so a typo'd key is rejected, not silently defaulted.
- Result envelope carries `structured_content = {render:{available, resource_link?, reason?}, scene:{rendered_objects, focused_on}}` per §3.9 outputSchema, plus the image as `images:[ImageRef]`. `available:false` → `resource_link` omitted, `reason` set, `status` still `OK` (unavailability is not an error).
- `camera` preset maps to a fixed orientation (iso = the axonometric quaternion); `custom` requires `custom_orientation` (4-float quaternion) — missing/malformed → `INVALID_INPUT`. `focus` frames the resolved sub-element/object bbox grown ~20% instead of whole-scene `viewAll`.
- **The renderer operates on the explicitly-passed document handle, never `FreeCAD.ActiveDocument`.** `RenderPort.render` takes the resolved `document` as a parameter (`render(document, scene, out_path)`); `OffscreenRenderPort` renders that document's objects. `ActiveDocument` is banned as a target (AD-20) — a screenshot of a handle must render that handle's doc even when a different (or no) document is active. The fingerprint before/after guard MUST fingerprint the SAME document the port renders (the resolved handle), so the read-only guarantee actually covers the rendered doc.
- **PNG lifecycle covers the whole render+verify.** The temp PNG is removed on EVERY non-OK path, not just when `render()` raises — a failing post-render `fingerprint()`/`fingerprints_equal()` (e.g. serializer-tag mismatch raising) must also remove the temp file before propagating. No path returns or raises with the temp PNG orphaned.
- Every FreeCAD/Coin call executes on the FreeCAD execution thread: GUI mode via the existing marshal (the listener already wraps dispatch); headless runs inline. Do not add a second marshal layer inside the handler.
- `shim.render_available()` and `capability_banner()['render']` become live probes driven by the ladder (replace the hardcoded `False`/`"none"`). All logging stderr-only; no `print()` (ruff T201).

**Block If:**
- `FreeCADGui.SoQtOffscreenRenderer` is not importable/usable on the supported 1.0/1.1 builds (no offscreen render primitive available at all) — HALT with the missing API and the observed alternatives; do not silently fall back to a banned raw pivy renderer or to whole-viewport `saveImage`.

**Never:**
- Never mutate the document, object `Visibility`, or the user's viewport to produce a render (constructed scene only). Never use raw `pivy.coin.SoOffscreenRenderer`. Never import `FreeCADGui`/Qt/`coin` in `usecases/` or `contracts/`. Never inline-base64 the PNG into the envelope. Never make render unavailability a hard error.
- Do NOT build the general geometric-query selector resolver (`surface_type`/`radius` predicate matching) — that shared resolver lands with the sub-element/mutation tools in a later phase. `focus`/`highlight` resolve only the cases addressable now: a whole object, or a direct sub-element by explicit `element_type` + index against `obj.Shape` (or a `mapped_name` selector when the element map is present). A `focus` naming a predicate query that cannot be resolved falls back to whole-object framing and echoes `focused_on` accordingly (see Design Notes).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Render available, no view opts | `{doc}`, render ladder `offscreen`/`gui_constructed` | `OK`; PNG ≤1024 px `resource_link`; `scene.rendered_objects` = all visible objects; fingerprint before == after | none |
| Include list | `{doc, view:{include:[Body]}}` | only `Body` subgraph in scene; `rendered_objects == ["Body"]` | none |
| Exclude list | `{doc, view:{exclude:[BasePlate]}}` | all visible minus `BasePlate` | none |
| Style override | `{doc, view:{styles:[{object:BasePlate, transparency:85}]}}` | `BasePlate` rendered with transparency material; others default; document unchanged | none |
| Focus sub-element | `{doc, view:{focus:{kind:..., object:Body, element_type:face, index:N}}}` | camera frames that face bbox +margin; `scene.focused_on` echoes the resolved selector | selector unresolvable → whole-object framing, echo object-only |
| Camera preset | `{doc, view:{camera:top}}` | scene rendered from top orientation | none |
| Custom camera missing quat | `{doc, view:{camera:custom}}` (no `custom_orientation`) | `INVALID_INPUT` (`custom_orientation required`) | fail closed |
| Render unavailable | ladder → `none` (no FreeCADGui / no GL) | `OK`; `render.available:false`, `reason` set, no `resource_link`; `capability_banner.render == "none"` | not an error |
| Oversized dims | `{doc, view:{width:4000}}` | clamped/validated to ≤1024 (schema cap) | `INVALID_INPUT` if schema rejects |
| Unknown doc handle | `{doc:"missing"}` | `INVALID_INPUT` via registry resolution | fail closed |

## Spec Change Log

### 2026-07-22 — bad_spec repair (loop 2)
- **Triggering findings:**
  - **Renderer targets `FreeCAD.ActiveDocument`, not the resolved handle (high).** The loop-1 re-derivation changed the `RenderPort.render` signature to `render(scene, out_path)` (no document) and `OffscreenRenderPort.render` reached for `FreeCAD.ActiveDocument` to get shapes. This is an AD-20 violation (`ActiveDocument` is a banned target), a correctness bug (in a multi-doc headless session it renders the WRONG document while `query_screenshot` fingerprints the correct resolved handle — so a wrong-doc image passes the mutation guard), and a `NoneType` crash when no document is active. Both reviewers flagged it as the dominant finding. The spec's loop-1 KEEP ("the port is handed a `SceneSpec`") was ambiguous about the document and let the signature drop it.
  - **Focus echo lies on fallback (medium).** When the focus object is excluded / not in the rendered set, has no `Shape`, or names an unresolved `mapped_name`/sub-element, the camera falls back to whole-scene/whole-object framing but `_focused_on_echo` still advertises the original sub-element selector — the response claims a framing that did not happen.
  - **Temp PNG orphaned on a post-render fingerprint failure (medium).** `_render_with_lifecycle` wrapped only `render_port.render(...)` in try/except-remove; a raising post-render `fingerprint()` or a `fingerprints_equal()` that raises on serializer-tag mismatch propagates with the temp PNG left on disk.
  - **Sub-element selector coherence (low).** A selector carrying BOTH `mapped_name` and `element_type`/`index` silently prefers `mapped_name` (index ignored); a non-string `mapped_name` is silently dropped rather than rejected — inconsistent with the otherwise fail-closed validation.
- **Amended (sections outside `<intent-contract>` only):** Code Map + Boundaries + Design Notes + Tasks now pin `RenderPort.render(document, scene, out_path)` — the resolved document is passed explicitly, `OffscreenRenderPort` renders THAT document, and `FreeCAD.ActiveDocument` is forbidden in the render path. The fingerprint guard fingerprints the same resolved document the port renders. The PNG lifecycle wraps the WHOLE render+verify (temp removed on a failing post-render fingerprint/compare too). `focused_on` echoes only the granularity actually framed (drop the sub-element part on any fallback). A selector with both `mapped_name` and `element_type`/`index`, or a non-string `mapped_name`, is `INVALID_INPUT`.
- **Known-bad state avoided:** a screenshot tool that renders whichever document happens to be active (wrong image, or a crash) while asserting read-only on a different doc; a response that confirms a sub-element framing that never occurred; a temp-PNG leak on the serializer-mismatch path; and silently-ignored selector fields.
- **KEEP (must survive re-derivation):** everything the loop-1 KEEP preserved PLUS the loop-1 fixes that were correct — the PNG-lifecycle ownership (`_render_with_lifecycle` remove-on-non-OK + non-empty-file check), `setupWithoutGUI()` gated on `offscreen` mode only, whole-object highlight granularity with no echoed sub-element accent, the coherent fail-closed input validation (`_require_object` for every include/exclude/styles/selector name, `_coerce_color`/`_coerce_transparency`/`_custom_orientation` raising `ValidationError`, partial-selector + degenerate-quaternion rejection), and the tightened `additionalProperties:false` schema. KEEP the ring-legal wiring, the cached ladder, the Gui-free usecase, `SoQtOffscreenRenderer` + `subgraphFromObject`, and ALL existing tests — add a **multi-document regression** (render doc A while doc B is `ActiveDocument`, assert A's objects are rendered) and the focus-fallback-echo + post-fingerprint-cleanup tests, do not replace.

### 2026-07-22 — bad_spec repair (loop 1)
- **Triggering findings:**
  - **Temp PNG lifecycle undefined (medium).** The render writes a `mkstemp` PNG and returns its path as the `resource_link`, but nothing ever deletes it and the mutation-detected raise + a `render()` exception both orphan the (possibly empty) file. The spec said "caller-independent temp path" without defining ownership/cleanup or a written-file check. Result: unbounded temp-dir growth and `resource_link`s that can point at a 0-byte file while the tool reports `OK`.
  - **Sub-element highlight is a silent no-op that the response lies about (medium).** `_resolve_selector` accepts an `element_type`+`index` highlight and the echo reflects it, but the renderer only applies the accent material when `highlight_element is None` (whole-object) — a face/edge highlight resolves, echoes, and renders nothing. The spec described "highlight = accent material on the resolved target" without pinning the resolvable scope, so the echo and the render diverge.
  - **`gui_constructed` render path calls `setupWithoutGUI()` unconditionally (medium).** `OffscreenRenderPort.render` always calls `FreeCADGui.setupWithoutGUI()`, including when the ladder already reported `gui_constructed` (a live GUI process). The spec put `setupWithoutGUI()` only in the offscreen ladder rung and never said the render path must gate it on the ladder mode.

## Design Notes

**RenderPort injection (the real wiring change).** Today `HandlerFactory` is `(DocumentRegistry, ExportRegistry, Capabilities) -> handler` — no render slot, and `usecases/` cannot import Gui. So the concrete renderer is a **host dependency**: define a `RenderPort` protocol (in `adapters/render_probe.py` or a small `contracts`/adapter module — keep it stdlib-typed), inject the `OffscreenRenderPort` at host startup, and thread it into `build_inline_handlers` so the `query_screenshot` handler closes over it. The usecase depends only on the protocol, never on a Gui import. One offscreen port serves headless and GUI — "GUI mode" only means `GuiUp` is true and the marshal runs the port's `render` on the Qt main thread (Coin is thread-affine); the port code is identical.

**Scene is composed, never mutated.** The renderer builds a fresh `SoSeparator` root per call and adds `subgraphFromObject(obj)` for each included object (a transient view provider — it does not alter the object). Exclude = don't add. Style = wrap that object's subgraph in its own `SoSeparator` with a prepended `SoMaterial` (transparency 0-1 from the 0-100 input; optional diffuse color). Highlight = an accent `SoMaterial` on the target's subgraph. Because nothing touches `Visibility`, the document, or the live viewport, the fingerprint-before==after assertion is a real guard, not decoration.

**Focus framing scope (boundary decision, not a gap).** Design §6 frames the focus selector's sub-shape bbox +~20% and aims the camera, "falling back to whole-object when the selector names an object only." The *general* geometric-query resolver (match `surface_type:Cylinder, radius:{value,tol}` etc.) is the shared sub-element resolver that the mutation/sub-element tools build later — building it here is out of scope (Never clause). For this story, `focus`/`highlight` resolve: (a) whole object → object bbox; (b) direct sub-element by `element_type` + index against `obj.Shape.Faces/Edges/Vertexes` → that sub-shape bbox; (c) `mapped_name` selector when the element map is present. A predicate-only `query` that can't be resolved yet falls back to whole-object framing and echoes `focused_on` as the object-level resolution. AC2 is satisfiable via (b)/(c). This keeps 1.9 honest without pulling in the Phase-2 query engine.

**Ladder ordering is load-bearing.** In the `offscreen` branch, `FreeCADGui.setupWithoutGUI()` MUST run **before** any other `*Gui` use and before touching a GL context (issue #16407 crash class). Probe with an 8×8 render of a trivial `coin.SoSeparator`; only a successful probe reports `offscreen`. Cache the ladder result once per process (`lru_cache`), matching the other `shim` probes.

**Testability without GL.** The usecase is proven headless-and-GL-free against a **fake `RenderPort`** (records the `SceneSpec` it was handed, returns a canned `RenderResult`/path), so every scene-spec mapping, the `custom` quat validation, and the `available:false` envelope are unit-tested in `tests/external` with no FreeCAD. The real Gui/Coin path (probe ordering, `SoQtOffscreenRenderer`, actual PNG) is proven only on the in-FreeCAD render CI leg (`tests/infc`, xvfb), non-blocking — mirroring how the GUI marshal path is left to the story-1.10 smoke.
