# Epic 3 Context: Confirmed Copilot (Phase 2 · gate G2)

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Epic 3 delivers Phase 2: a user issues one natural-language modeling command, sees a structured preview diff of exactly what would change, confirms it, and gets a verified mutation — or a mutation that provably never happened. It turns Epic 1's read-only bridge into a writing bridge without ever letting the document reach an unverified state: every mutation runs through one transaction wrapper with hash-proven rollback, every reference is audited for silent topological-naming breakage after every op, and undo is proven by re-hash rather than assumed. Gate G2 is passed only when the sealed 40-command benchmark runs green on geometry assertions authored before the code existed, with 100 % post-verify/rollback and undo proof, 5/5 TNP scenarios flagged, and a human `spot_audit` token bound to the run.

## Requirements & Constraints

- **One mutation path, no exceptions.** Every `sketch_*` / `feature_*` / geometry-intent `document_*` tool executes through the single `run_mutation()` wrapper. No mutation happens outside a bridge-owned transaction — including headless, where FreeCAD opens none on its own and undo is silently a no-op without an explicit `openTransaction`.
- **Rollback is measured, never assumed.** After abort, the document is recomputed and re-hashed; equality with the pre-op fingerprint is the only evidence of restoration. Hash mismatch escalates to restore from the pre-op `saveCopy` snapshot, which is then re-hashed again. A snapshot is taken before every mutation and deleted only after commit or verified rollback — in-memory undo history is capped and untrustworthy alone.
- **Exact undo.** For every benchmark op, fingerprint-before must equal fingerprint-after-undo in 100 % of cases. The snapshot-restore path counts as success but must be reported when taken.
- **TNP guard never reports clean when it cannot see.** If the element-map capability probe fails, every reference verdict is `UNSUPPORTED` — never `PASS`. An `ElementMapVersion` bump re-baselines the snapshot instead of failing.
- **Preview before confirm before mutate.** No geometry-intent mutation executes without a valid `confirm`. Confirmation gates on the structured diff, never on pixels — renders are optional and capability-gated.
- **Single writer.** Mutations on one document are serialized; AD-5 transactions never interleave. Every tool call carries an explicit document handle; `ActiveDocument` is never an implicit target.
- **Preview never touches the live document.** The dry-run runs on a `copyObject` TempDoc under a reserved name prefix, flagged transient, cleaned by its creator alone. The live document's fingerprint must be unchanged across a preview.
- **Sketches must reach `FullyConstrained`.** That property, read after `doc.recompute()`, is the only PASS signal. Redundant/partially-redundant constraints warn but never fail; conflicting, malformed, degenerate, or non-zero DoF hard-fail.
- **Assertions grade intent, not success.** A recompute that completes is not a pass — per-command geometry assertions check the right feature in the right place at the right size. They were authored analytically from known golden-model geometry, never captured from a verify tool.
- **Audit everything.** Every mutation, preview, approval, and rollback writes an audit record. Auto-approvals record the digest of the diff that was auto-accepted.
- **In-FreeCAD purity and version shim** carry over unchanged: stdlib + FreeCAD API only inside the process; every version-sensitive call behind the capability-probe shim; blocking CI on FreeCAD 1.0.x and 1.1.x.

### G2 Exit Criteria (what "done" means for the epic)

- G2.1 Command benchmark: 40 commands × 8 op types on reference models at R=5, scored by per-command geometry assertions — **≥85 % first-attempt pass**.
- G2.2 Universal post-verify + rollback: inject failing ops, read audit log + reports — **100 %** of executed ops show a post-verify record, and every failed verify shows automatic rollback plus a human-readable explanation.
- G2.3 Exact undo: fingerprint before → mutate → undo → fingerprint after, for every benchmark op — **hash-identical in 100 %** of cases (snapshot-restore path counts and is reported when taken).
- G2.4 TNP guard: the 5 TNP-provoking scenarios through the guard — **5/5 flagged, zero false-clean**, and `UNSUPPORTED` never reported on the CI matrix legs.
- G2.5 Fully constrained sketches: read `verify_sketch` reports over the sketch benchmark — **`FullyConstrained == True` in ≥90 %**.
- G2.6 Skills + ablation harness: shape-check the 6 newly drafted skills, run the ablation with declared subsets — harness reports **per-skill paired deltas** in the standard ablation format.
- Exit run is R≥10 on the unsealed held-out set; dev/held-out gap must be **≤15pp**; a `spot_audit` human token must be bound to the run. Fault suites sit beside the dev/held-out split and never count toward any pass rate.

## Technical Decisions

- **The `run_mutation()` bracket (AD-5), in exact order.** Outside the transaction: fingerprint the document, snapshot references, take a `saveCopy` snapshot to a reserved-prefix temp path. Then `openTransaction` (fresh id 0 — cross-document grouping is deliberately unused) → apply the typed op → `doc.recompute()` → `post_verify` → on pass `commitTransaction`, delete the snapshot, return an OK envelope with the after-fingerprint. On failure or exception: `abortTransaction` → `recompute()` (mandatory — recompute is skipped during undo, so verification before it reads stale state) → re-fingerprint; equal to before means `rolled_back_verified`, otherwise restore from the snapshot, recompute, and re-assert equality, giving `rolled_back_via_snapshot`. Never nest transactions and never leave one open: opening a new one silently auto-commits a stray open one and wipes the redo stack, which is itself a rollback-boundary trigger. One transaction per tool call.
- **`post_verify` checklist order** (cheap → expensive, short-circuit on first hard failure): (1) recompute clean — no object failing `isValid()`, collecting `getStatusString()` per failure; (2) shape validity via `verify_shape` on every shape-bearing object the op touched; (3) sketch signal via `verify_sketch` on every sketch involved, requiring `FullyConstrained`; (4) TNP audit against the pre-op reference snapshot, where any BROKEN/REPOINTED/DROPPED verdict fails the mutation.
- **Fingerprint (AD-6).** One implementation only. SHA-256 over per-object serialized shape bytes with objects sorted by immutable `Name`, plus a quantized mass-property tuple as an independent cross-oracle. The serializer is capability-probed once per process and every fingerprint carries its tag; comparing across tags is banned and the comparison helper raises. Digest equality is the primary signal; BRep-hash/mass-prop disagreement on a benchmark run is a validator bug to investigate, never to average away. Scope is representation identity — the right oracle for undo/rollback proof, and deliberately not a geometric-equality test.
- **TNP guard layers (AD-7).** `snapshot_references` records one entry per subelement link across the four reference-holding subsystems (Sketcher external geometry, attachment/datums, PartDesign profile/base, expression-engine dependencies) with the `(mappedName, indexedName)` shadow pair, a resolution witness, entry count, and the owner's `ElementMapVersion`. `audit_references` then runs, after mutate → recompute: **Layer 0** error sweep over `isValid()`/`getStatusString()`; **Layer 1** mapped-name diff, the guard proper — missing-element marker or null `getElement` → BROKEN, resolves but mapped name or witness changed while not the op's intended target → REPOINTED, a LinkSubList that lost entries vs snapshot → DROPPED (entry-count comparison is mandatory; an error-status check alone misses the dressup silent drop); **Layer 2** history cross-check via `getElementHistory`, run only where Layer 1 is ambiguous — divergent ancestry on an unchanged reference is REPOINTED even when witnesses coincide.
- **Verdict enum:** `PASS | BROKEN | REPOINTED | DROPPED | UNSUPPORTED`, reported per reference alongside owner, prop, mapped-name-before, state-after, the layer that decided it, and detail. Any non-PASS fails the mutation and rolls it back, with one exception: if an owner's `ElementMapVersion` differs from its snapshot value, its entries are **RE-BASELINED** — the snapshot is re-taken and the audit does not fail, but the re-baselined entries are still reported so drift stays visible. No element map at all → `UNSUPPORTED`, never clean.
- **The `mutation` result block** returned by every mutation tool: `transaction_id`, `fingerprint_before` and `fingerprint_after` (each `{hash, serializer, mass_props}`), `post_verify` containing `recompute_clean`, `is_valid`, `fully_constrained`, and `tnp_audit` (`{status: CLEAN|FLAGGED|UNSUPPORTED, element_map_version, findings}`), plus `rolled_back` and `rollback_proven`.
- **Preview payload.** `preview_dry_run` takes the live doc plus `{tool, args}` for any registered mutation tool and returns `preview_id`, an `expires_at`, and a mandatory structured diff: volume/area/bbox/COM deltas, face/edge/vertex/solid count deltas, `touched`/`new`/`deleted` node names, `validity` (`is_valid`, `recompute_clean`, recompute errors), `tnp_precheck` (same CLEAN/FLAGGED/UNSUPPORTED status vocabulary, surfaced verbatim — the preview never claims clean), and `fingerprint_before`. Renders are an optional capability-gated overlay and accept the same view-control object as the read-only screenshot tool (e.g. focus the camera on the edge being filleted). The diff must reuse the existing audit-record vocabulary — `fingerprint_before/after`, `verify_verdict`, `params_digest`, `touched/new/deleted` are shared identifiers, and no synonyms may be introduced.
- **Confirmation flow.** The confirm object carries `preview_id`, an `elicitation_action` of `accept` (decline/cancel never reach the mutation tool), and an optional headless-only `autoApprove`. A mutation tool called without a valid confirm in a confirm-required context returns `INVALID_INPUT` and does not execute. Three contexts: GUI/MCP elicitation, client-confirm token fallback, and headless — which is fail-closed unless `autoApprove` is explicitly set, and every such use writes an approval audit record with the diff digest. Apply **re-runs** the op on the live document under the full AD-5 bracket; the preview result is never promoted to the live doc.
- **Lifecycle-op exemption.** `document_save`, `document_close`, `document_recompute`, and `document_undo` change document state but carry no new geometric intent. They are audit-logged and serialized under the single-writer rule, but are exempt from the AD-5 snapshot bracket and from the preview/confirm gate. `document_undo` is itself the rollback mechanism and is verified by fingerprint comparison (G2.3). `document_object_delete` is **not** exempt — it carries geometric intent and runs the full bracket.
- **Sub-element addressing.** Feature and sketch tools take geometric selectors (surface type, radius band, axis direction, position region) and resolve them to mapped names at call time. Stored indexed names are banned as inputs, and every dimension is an explicit-unit `Quantity`. Feature names are mandatory and intent-bearing so the tree reads as a build plan.
- **Sketch tool contract.** Every sketch tool returns a `sketch_state` block (the embedded `verify_sketch` summary) plus the common `mutation` block. Solver diagnostics use 1-based constraint ids mapped to `Constraints[id-1]` names; conflicting or malformed sets roll back automatically with those named diagnostics attached.
- **Registry profiling.** The Phase 2 profile adds `sketch_*`, `feature_*`, `preview_*`, and the remaining `document_*` tools behind the confirm gate. `debug_exec` stays out of every AI-facing registry and out of `preview_dry_run.operation.tool`.
- **Tolerances are calibrated, not guessed.** Per-assertion tolerance defaults are tuned against the planted fault suites until each validator clears sensitivity ≥95 % / false-alarm ≤5 %. No assertion may be tighter than the measured shape's own `Shape.getTolerance`.

## UX & Interaction Patterns

- Confirmation is evidence-based: the user (or agent) decides from the structured diff, which is always present, not from a render, which may not be. Renders are ≤1920 px, annotated for the user audience, and delivered as resource links rather than inline base64.
- The three confirm contexts are one behavior with three carriers — GUI panel / MCP elicitation, `preview_id` token fallback, headless fail-closed. The posture, not the transport, is what the mutation tool checks.
- Failure is explained, not just reported: a failed post-verify must produce a human-readable explanation alongside the rollback record (a G2.2 pass rule, not a nicety).
